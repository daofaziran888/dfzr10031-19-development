# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 智能告警：阈值判定与事件清单

规则本身只登记监控指标；判定要另外给出规则编号、指标编号和观测的业务时刻。

- `POST /api/alert/evaluate`：按规则的「阈值条件」（如 `> 90`、`< 70 持续10`）判定一批观测，
  返回超限时段与事件变更。观测按业务时刻排序，登记顺序不影响结论。
- 连续超限观测合成一个超限时段；恢复观测在它的业务时刻收口，恢复段不计入超限时长；
  缺测观测既不判超限也不判恢复，会列在事件的「缺测依据」里。
- 同一批观测重复提交是幂等的：事件数、累计超限分钟、每段超限时段都不会扩大。
- 迟到观测按业务时刻插回全量观测历史后重算。已确认的处置保留首次签认，变化部分写入
  变更清单，值班人员在审计页能看到迟到数据影响了哪些处置对象。
- 10:00、10:10 超限已确认，补到 10:05 恢复时，两种合并口径都支持：
  - `merge`（默认）：保留同一项处置并附两段实际超限时长，恢复段被排除；新出现的未收口
    时段在 `review_required` 里标出，可只确认该时段。
  - `split`（规则阈值条件末尾写「拆分」，或判定时传 `合并口径=split`）：已确认处置保留
    10:00-10:05，从 10:10 起拆出第二项待确认处置。
- 前端「智能告警」页分「告警规则 / 阈值判定 / 事件清单」三个页签；「数据审计」页分
  「审计记录 / 告警变更审计 / 重放核对」，重放同一批判定观测后核对事件数、覆盖时段和处置对象。

自带示例规则：`ALER-0001`（`> 90`，合并口径）、`ALER-0002`（`< 70`）、`ALER-0003`（`> 90 拆分`）。

后端测试不依赖 pytest：

```bash
cd backend && .venv/bin/python -m unittest discover -s tests -t . -v
```


## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
